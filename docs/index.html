itakua

A safe map for a personal knowledge base

Itakua decides where every file goes, which writes need approval, and how the tooling keeps a brain honest about its declared boundaries.

What's here

PluginWhat it does
itakua Nodes, four slots, per-node READMEs. Stands a brain up, then validates it — including whether the repository's git remote and identity match what the brain says they are.

How Itakua is put together

One folder tree, two storage systems, and they never overlap. That is the whole idea — everything else follows from keeping those subtrees disjoint.

The parts worth knowing

A node is any folder with a README.md. All nodes live under spaces/. Nesting means containment, not lifecycle — a project inside a space is nested because it lives there, not because it ends. Whether a node ever finishes is something its own README declares.

Four slots, and one rule that closes the system: a folder is either a slot, or a child node with its own README. Anything else is temporary. That single sentence is what the validator enforces, which is why the structure doesn't quietly rot into invented folders.

notes/ changes with owner approval; log/ is append-only. Notes say what's true now. Logs preserve dated raw evidence, and corrections arrive as later entries instead of rewriting history.

docs/ is the durable-artifact boundary. Creation and editing require owner approval. Binaries live in cloud storage; git holds an approved generated index so the Markdown side knows what exists.

_tmp/ is manual staging. New nodes include it by default. Scheduled and unattended passes do not process it, and nothing there is deleted without owner approval.

Install with Claude

claude plugin marketplace add <this repo>
claude plugin install itakua@itakua
Then restart your session. Skills are enumerated when a session starts, so a mid-session install stays invisible — and it fails with the same error as never having installed anything. This cost two test runs to find. Skills also install per account, not per machine: two accounts on one computer need two installs.

Install with Codex

codex plugin marketplace add <path-to-itakua>
codex plugin add itakua@itakua
Then start a new Codex task. Claude and Codex use separate discovery metadata, but both load the same itakua-map skill and scripts.

Start a brain

new-brain.sh ~/Documents/mybrain "My Brain" \
  --identity "Your Name <you@example.com>"

Add --local-only for a brain whose material must never reach a hosted remote — it configures no remote, which is the entire control. Then run the validator; it will tell you what the brain still needs.

Your knowledge stays in plain markdown, in a git repository you own. The framework has no opinion on which accounts you use — a brain binds its own path, git remote, storage account and agent account, and declares them in its README.
